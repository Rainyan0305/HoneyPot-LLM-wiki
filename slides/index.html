蜜罐是什麼？

一個故意做得很誘人的「假目標」，
讓駭客自己走進來、被我們看清楚。

按 → / 空白鍵 換頁，← 上一頁

先想像一個情境

家裡放一個「看起來裝滿現金」的保險箱，其實是空的，上面裝了監視器。

  • 家人知道它是假的，不會去開
  • 所以只要有人開它 → 一定是小偷
  • 監視器還錄下他怎麼開鎖

這個假保險箱，就是電腦世界的蜜罐。

正式定義

NIST（美國國家標準與技術研究院）

刻意設計成對入侵者有吸引力的
系統（例如網頁伺服器），
或系統資源（例如一個檔案）。

就像蜂蜜吸引熊

Lance Spitzner（Honeynet Project 創辦人）

蜜罐的價值，就在於它被探測、被攻擊、被入侵。

一般系統怕被攻擊；蜜罐「被攻擊」才有用

重點：蜜罐可以大到一整個網路，也可以小到一個檔案。

反過來想：把駭客「請進來」

一般資安工具

防火牆、防毒：
想把駭客擋在外面

蜜罐

故意讓駭客進來，
在受控的地方觀察他

為什麼誤報很少？

蜜罐沒有正常用途，
會碰它的幾乎都是攻擊者

名字來自諜報界：用誘惑讓目標上鉤，再從他身上取得情報。蜜罐屬於「被動防禦」，不會主動攻擊別人。

蜜罐的小歷史

1990/91

Stoll《The Cuckoo's Egg》與 Cheswick 的 Berferd 論文，最早公開記錄這種做法

1991.1

AT&T 貝爾實驗室發現有人想偷密碼檔，故意寄假檔給他，再把他關進「監獄」觀察

1997–98

Deception Toolkit、CyberCop Sting：第一批給大家用的蜜罐工具

1999

Lance Spitzner 成立 Honeynet Project 國際研究組織

2003–13

攻擊者開始研究「怎麼認出蜜罐」

近年

用 LLM 即時產生假檔案和回應，更難被識破

⚠ 有網路文章說 AT&T 事件在 1990 年；原始論文寫的是 1991 年 1 月 7 日，這裡採用原始論文。

蜜罐怎麼運作？五個步驟

最後一步最重要：蜜罐本身不會擋攻擊，要把學到的東西拿去強化真正的系統。

蜜罐能看到什麼？

  • 攻擊者從哪個 IP 位址來
  • 他試了哪些帳號密碼、拿到什麼權限
  • 他看了、改了、刪了哪些資料
  • 他想放進來的惡意程式

因為正常人不會來，這些紀錄幾乎都是「純攻擊」資料，分析起來很乾淨。

例：Cowrie（開源 SSH 蜜罐）的紀錄長這樣（示意）

登入嘗試 root / 123456 → 「成功」
$ uname -a
$ wget http://…/bot.sh
→ 檔案已保存，等待分析
$ cat /etc/passwd
→ 看到的是假檔案

整段連線還可以「重播」，看攻擊者當時怎麼打字。

分類一：為了什麼目的？

生產型蜜罐

  • 一般企業使用
  • 目的：抓自家網路裡的攻擊
  • 簡單、便宜，最常見
  • 缺點：只看得到自己的網路

研究型蜜罐

  • 大學、政府、資安公司使用
  • 目的：研究駭客的工具、手法、動機
  • 複雜、成本高
  • 能看到更廣的攻擊趨勢

比喻：生產型＝店裡的防盜警報；研究型＝警察的誘捕研究小組。

分類二：做得有多「真」？

低互動中互動高互動
是什麼只假裝幾個服務模擬部分系統，可以下指令完整的真系統
比喻門口的假監視器逼真的樣品屋真房子，但整棟被監控
成本低中高
風險低中高
得到的資料基本統計指令、惡意程式最完整
被識破很容易中等較難

大多數生產型是低互動；大多數研究型是高互動。上一頁的 Cowrie 屬於中互動。

分類三：想抓哪一種攻擊？

垃圾郵件陷阱

只有自動爬蟲找得到的假信箱，寄來的信都是垃圾郵件

誘餌資料庫

故意有漏洞的假資料，抓想偷資料的人

惡意程式蜜罐

假裝是軟體或 API，把惡意程式引進來研究

蜘蛛蜜罐

只有爬蟲看得到的網頁，找出惡意機器人

同一個想法，三種尺寸

蜜標：一筆假資料

假帳號、假金鑰、誘餌文件。
問：「有沒有人碰了不該碰的？」
成本最低

蜜罐：一個假系統

假伺服器、假資料庫。
問：「攻擊者進來後做了什麼？」

蜜網：一整個假網路

多個蜜罐連在一起。
問：「攻擊者怎麼在系統間移動？」

好處與風險

👍 好處

  • 誤報少：碰它的幾乎都是壞人
  • 早發現：像一條絆線
  • 看得到攻擊怎麼演變
  • 外部駭客、內部人員都抓得到

⚠ 風險

  • 變成跳板：隔離沒做好，駭客從假系統跳進真系統
  • 被反利用：灌假流量、故意餵錯資訊
  • 不是萬靈丹：不會擋攻擊，也不會修漏洞
  • 高互動很貴，需要專人

駭客也會「認出」蜜罐

  • 低互動蜜罐只是「模仿」，細節很難做到完美 → 幾乎一定能被認出來
  • 實例：掃描工具 Nmap 能認出某些蜜罐；搜尋引擎 Shodan 有「honeyscore」幫人判斷
  • 所以低互動適合抓自動化的攻擊；想觀察高手，要用調校過的高互動蜜罐
  • 新做法：用 LLM 即時產生逼真回應

假監視器嚇得跑小賊，
但專業小偷一眼就看出沒插電。

這是一場「識破 → 修補 → 再改進」的循環

想放蜜罐？六個原則

1 先定目的

保護自家網路，還是做研究？

2 隔離

和真系統分開，避免變跳板

3 量力而為

小團隊從低互動或蜜標開始

4 做得像真的

改掉預設值；不要取名「honeypot.txt」

5 接上警報

沒人收到通知的誘餌等於沒用

6 持續維護

不是裝了就不管；搭配其他防禦

重點回顧

  • 蜜罐＝故意做得很誘人的假目標
  • 沒有正常用途 → 碰它的幾乎都是攻擊者
  • 流程：擺誘餌 → 留破綻 → 記錄 → 分析 → 強化真系統
  • 越真（高互動）→ 資料越多，但越貴、越危險
  • 蜜標 < 蜜罐 < 蜜網：同一想法，不同尺寸
  • 一定要隔離、接警報、持續維護
